Simpro与Xero自动同步发票避坑指南

刚把 Simpro 和 Xero 打通同步,感觉像打通了任督二脉——结果发票重复、税码对不上、付款状态乱跑,账反而越对越乱。这篇是踩过坑之后的真实总结,帮你少走弯路。

先搞懂同步是单向还是双向

Simpro 推数据到 Xero 是默认行为,但如果你在 Xero 那头改了发票金额或备注,改动不会自动回流到 Simpro。两边手动改过的记录最容易打架,改之前要想清楚「谁是数据的唯一源头」,定好规矩再动手。

税码映射没做好,GST 会出大问题

Simpro 里的税率和 Xero 的 Tax Code 要一一对应好,这一步很多人跳过了。最常见的坑是含 GST 的项目映射到了 Xero 免税的 Code 上,BAS 一出来就差一截。设置完之后一定要用一张真实发票人工核对一遍数字,别只靠系统说「成功」就信了。

发票状态不一致是正常现象

Xero 里标了「已付」,Simpro 那边不一定同步更新,反过来也一样。能不能开双向状态回写、怎么配置,各版本和套餐差异较大,以 Simpro 官方文档或持牌实施顾问为准。自己瞎改同步设置很容易造成状态混乱,改一个地方要想清楚对另一边的影响。

重复发票是这样跑出来的

最常见两个原因:一是同一张发票在 Xero 手动建了一次,又让 Simpro 自动推了一次;二是误触了全量重新同步,历史记录又推了一遍。解决方案很简单——发票只在一个系统里创建,另一个只读不写,形成习惯之后重复问题基本消失。

出错了先查这两个日志

Simpro 的 Integration Log 会记录每次同步的结果和报错,是排查问题的第一入口。Xero 那边看 Activity Log 和 History & Notes。两边日志对照着看,大部分问题能定位到具体那张发票。看不懂的报错不要凭感觉乱改设置,直接联系 Simpro 官方支持或持牌顾问效率更高。

👉 上线前先用一两张测试发票跑一遍全流程,确认税码、金额、付款状态三样都对了,再放开正式批量同步——事后修数据比预防要痛苦十倍。
